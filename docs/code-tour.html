Backend — FastAPI REST API
backend/main.py
The entire server in one file (668 lines). Defines all REST API endpoints, request/response models (Pydantic), and mounts the SPA static files. Also includes the 4-artist validation block that prevents unknown IDs from getting fake-organic verdicts.

Key endpoints:
POST /analyze
Full 7-signal analysis for the 4 study artists. Runs the complete pipeline with Neo4j + Kaggle data. Returns all 7 scores + GNN verdict.
POST /analyze-live
3-signal live analysis for any Spotify artist. Fetches real data from Spotify + YouTube + iTunes. Returns S2, S5, S7 scores.
GET /search?q=artist+name
Search Spotify by artist name. Returns top 5 matches with photo, follower count, popularity. Powers the search dropdown in the Analyzer.
GET /graph/neighborhood/{id}
Returns ISRC bipartite neighborhood data for the Network page graph visualization.
POST /chat
Sends a question to GPT-4o with research context injected. Powers the AI Research Assistant page.
GET /health
Health check — returns Neo4j connection status and signal availability.
API Clients — External Service Wrappers
src/api/spotify_client.py
Spotify API wrapper. Wraps the spotipy library with disk caching and rate limiting. All responses saved to data/raw/cache/ as JSON. Key methods: search_artists(name), get_artist(id), get_artist_albums(id), get_album_tracks(id). Reads credentials from .env.
src/api/youtube_client.py
YouTube Data API v3 wrapper. Searches for an artist name, finds the top video result, returns view count. Uses the "two-pass" approach: first search for artist channel, then get most-viewed video. Requires YOUTUBE_API_KEY.
src/api/apple_music_client.py
iTunes Search API wrapper. No authentication needed — free public API. Queries itunes.apple.com/search?term={name}&entity=musicArtist. Returns whether the artist appears in Apple Music and their Apple Music genre/link if found.
Graph Database — Neo4j Interface
src/graph/neo4j_client.py
Neo4j AuraDB connection wrapper. Connects to the cloud graph database using credentials from .env. Provides a run(cypher_query, **params) method that executes Cypher queries and returns results as Python dicts. Used by all signal modules that need album/track/ISRC data. Includes retry logic for connection drops.
Signal Modules — The 7 Detection Algorithms
src/signals/audio_similarity.py
Signal 1: Audio Feature Variance. Loads the Kaggle dataset, filters to the target artist, computes total variance across [danceability, energy, valence, acousticness]. Returns a suspicion score: 0.0 (organic, high variance) to 1.0 (ghost, near-zero variance). Threshold: variance < 0.050.
src/signals/cadence_sync.py
Signal 2: Release Cadence Synchrony. Queries Neo4j for album release dates. Computes closure rate (fraction of consecutive release pairs ≤ 1 day apart), burst ratio (max releases in 7-day window), and runs Isolation Forest anomaly detection on gap sequences. Includes pre-computed closure rates for the 4 known artists in _KNOWN_CLOSURE dict.
src/signals/playlist_cooccurrence.py
Signal 3: ISRC Attribution / Playlist Co-occurrence. Looks for shared ISRC prefixes between artists. Computes Jaccard overlap of ISRC prefix sets. Returns a network-level suspicion score. Currently a null result for the 4-artist seed set (no shared prefixes) — becomes meaningful at scale.
src/signals/follower_ratio.py
Signal 4: Catalog Density / Upload Velocity. Computes tracks_per_day = total tracks / career span in days. Threshold: > 0.15 tracks/day is suspicious. Also looks at follower-to-track ratio (ghost artists have surprisingly few followers for their catalog size).
src/signals/metadata_similarity.py
Signal 5: Metadata / Title Similarity. Two approaches: (1) keyword pattern matching (e.g., ambient/relaxation genre terms), and (2) sentence-transformers cosine similarity on track titles. Returns suspicion based on how cookie-cutter the title naming pattern is. Most effective for artists with template naming (e.g., "White Noise for Sleeping Vol. X").
src/signals/graph_density.py
Signal 6: HHI Graph Density. Queries Neo4j for all tracks and their ISRC prefix (production company). Computes HHI = Σ(fraction²) per company. Returns suspicion score that scales with concentration. Also computes degree centrality of each artist in the bipartite graph.
src/signals/cross_platform.py
Signal 7: Cross-Platform Discrepancy. Calls the YouTube client to get view count, calls the iTunes client to check Apple Music presence. Returns a suspicion score: very low cross-platform presence = suspicious. Handles the ambient/relaxation exception (high views ≠ organic in this genre).
src/signals/verdict.py
Master verdict scorer. Calls all 7 signal modules, collects scores, computes weighted average (or simple mean for available signals), runs the trained GNN if available, and returns the final verdict dict: {verdict_score, verdict_label, signals, confidence, explanation, gnn_score}. This is the function called by POST /analyze.
Models — Neural Network Definitions
src/models/gnn_detector.py
GNN model class definitions. Contains GhostDetectorGAT (primary — Graph Attention Network with 4 attention heads) and GhostDetectorGCN (baseline — Graph Convolutional Network). Both take an 8-feature node feature matrix and an edge index, and output a probability per node. Load trained weights with model.load_state_dict(torch.load('data/processed/gat_model.pt')).
src/models/dataset_builder.py
Graph dataset constructor. Reads exercise outputs (closure rates, HHI, variance tables) + Kaggle ghost/organic lists. Builds the PyTorch Geometric Data object with node features, edge index, and train/val/test masks. Saves to data/processed/gnn_dataset.pt. Called once during setup; not needed at inference time.
Agents — CrewAI Orchestration
src/agents/crew.py
Main orchestration entry point. Provides two functions: run_analysis(artist_id) (fast, no LLM — just calls signal modules) and run_analysis_with_crew(artist_id) (slow, uses GPT-4o — full CrewAI pipeline). The former is what the FastAPI backend uses; the latter is experimental. Also provides run_batch_analysis(artist_ids) for processing multiple artists.
src/agents/crawler_agent.py
Data fetching agent. In the CrewAI pipeline, this agent's job is to pull all raw data for an artist from Neo4j and the Spotify cache. Outputs a structured data bundle for the fingerprint analyst.
src/agents/fingerprint_analyst.py
Signal computation agent. Receives the raw data bundle from the crawler, runs each signal module, and returns the 7 scores. The "analyst" persona makes it interpretable in LLM-backed mode — GPT-4o can reference it by role.
src/agents/graph_builder.py
Graph analysis agent. Builds and analyzes the ISRC bipartite neighborhood for the target artist. Returns adjacency information and HHI scores for the verdict agent to use.
src/agents/verdict_agent.py
Final verdict synthesis agent. Receives all 7 scores + graph analysis. Produces the final verdict label, confidence score, and natural language explanation. In LLM mode, this explanation is generated by GPT-4o. In pipeline mode, it's a template-filled string.
Ingest — Data Loading Pipelines
src/ingest/seed_ingest.py
Seed data loader. Fetches the 3 known ghost artists + 1 organic control from Spotify and loads them into Neo4j. Run once during project setup to populate the database. Uses the Spotify API to get albums and tracks, then writes nodes and relationships to Neo4j via Cypher MERGE statements.
src/ingest/live_ingest.py
Live artist pipeline. Provides search_artist(name) (searches Spotify by name, returns top 5 matches) and analyze_live(artist_id, run_s7) (fetches albums/tracks for any artist, runs S2+S5+S7, returns verdict dict in same format as run_analysis()). This is what powers the POST /analyze-live endpoint and the name search dropdown.
Utilities — Helpers and Config
src/utils/config.py
Centralized configuration. Reads all environment variables from .env using python-dotenv. Provides typed constants: SPOTIFY_CLIENT_ID, NEO4J_URI, OPENAI_API_KEY, signal thresholds, file paths. All modules import from here instead of reading .env directly.
src/utils/ground_truth.py
Ground truth labels. Python dict mapping the 4 artist Spotify IDs to their known labels (ghost/organic) and source citations. Used by signal modules for calibration and by the verdict module for label lookup. The 3 ghost labels are journalist-confirmed; the organic label (Nils Frahm) is from established critical reception.
src/utils/kaggle_loader.py
Kaggle dataset loader. Reads data/kaggle/dataset.csv into a pandas DataFrame. Provides helper functions: get_artist_tracks(artist_name) (filter to one artist), compute_variance(df) (audio feature variance). Handles the multi-artist string format in the Kaggle dataset (artists stored as "[Artist1, Artist2]").
src/utils/rate_limiter.py
API rate limiter. Implements exponential backoff: if an API call fails (rate limit hit), wait 1s, then 2s, then 4s, up to a max. Wraps the Spotify and YouTube clients. Prevents the app from getting banned for making too many requests too fast.
Frontend — Single-Page Application
static/index.html
The HTML shell. Just 30 lines. Contains the nav bar (links that call navigate()), an empty <div id="page-root">, and a <script> tag loading app.js. All actual content is injected by JavaScript.
static/css/styles.css
All styling. Dark theme with CSS custom properties (variables) for colors. Includes the GhostTrack brand palette, animation keyframes (stat counters, waveform), responsive grid layouts, signal bar colors, badge styles. ~1,000 lines total.
static/js/app.js
The entire application in one file (~850 lines). Key sections:
  • KNOWN_ARTISTS — Array of 4 study artist objects with Spotify IDs
  • navigate(page) — Swaps page content without reload
  • renderHome() — Hero + stat cards + findings
  • renderGallery() — 8 figure cards with download links
  • renderAnalyzer() — Search box + quick picks + results area
  • onArtistInput() — Debounced search-as-you-type
  • _fetchSuggestions(q) — Calls GET /search?q=...
  • runAnalysis(artistId, isLive) — Routes to /analyze or /analyze-live
  • renderAnalysisResult(data) — Renders signal bars, verdict badge, explanation
  • renderNetwork() — ISRC graph + cross-platform table
  • renderAI() — Chat interface, calls POST /chat
  • renderAbout() — Tech stack, architecture, limitations
Paper / Documentation
paper/SUPPLEMENTARY_MATERIALS.md
Academic supplementary materials index. Tables of all figures, datasets, signal computation details, known limitations, and reproducibility instructions. Submitted alongside the research paper for INFO 7390.
paper/S4_instructors_guide.md
Full instructor rubric. Per-exercise rubrics with expected outputs, acceptable ranges, common student mistakes, grading notes, and FAQ. Every exercise's expected key metric is documented with tolerances.
paper/figures/
24 publication figures. PNG and PDF versions of all 8 main figures + supporting charts from exploration. Named fig1_ through fig8_ for the main figures, plus Kaggle EDA charts.

Running the Project

Step 1: Install dependencies

cd /path/to/eda-for-music
python -m venv venv           # Create virtual environment
source venv/bin/activate       # Activate it (Mac/Linux)
# or: venv\Scripts\activate   # (Windows)
pip install -r requirements.txt

Step 2: Configure environment

cp .env.example .env
# Open .env in any text editor and fill in your API keys

Step 3: Start the server

uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload

Then open http://localhost:8000 in your browser.

Step 4: (Optional) Run the notebooks

jupyter notebook notebooks/

Open each notebook in order (01 through 10) and run all cells.

API documentation

FastAPI auto-generates interactive API docs. Open http://localhost:8000/docs to explore all endpoints, see request/response schemas, and test them live from the browser.

Minimum requirements: Python 3.10+, 4GB RAM (for sentence-transformers model), active Neo4j AuraDB connection, Spotify developer credentials. YouTube API key and OpenAI key are optional — the core analysis works without them.
